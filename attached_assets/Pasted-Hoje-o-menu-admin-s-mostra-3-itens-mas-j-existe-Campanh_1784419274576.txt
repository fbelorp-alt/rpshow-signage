FASE 2 — Novas páginas (usar APIs existentes)
Cada página: PageHeader + filtros (período / cliente / tela quando fizer sentido) + KPIs resumo + tabela + botão Imprimir / PDF (mesmo HTML print dos outros).

A) Exibições — /reports-admin/exibicoes
Arquivo: reports-exibicoes-admin.tsx
API: GET /api/reports/plays?from=&to= (+ filtros se existirem)
Colunas: mídia, tela, cliente (se admin), início, fim, duração
KPIs: total plays, tempo total, telas distintas, mídias distintas
Uso: auditoria do que rodou no período.

B) Por Tela / Player — /reports-admin/por-tela
Arquivo: reports-por-tela-admin.tsx
API: GET /api/reports/by-player + GET /api/reports/activation
Colunas: tela, código, plays, tempo total, última atividade, status ativação
KPIs: telas ativas no período, % com plays, média plays/tela
Uso: quais players performam / estão parados.

C) Top Mídias — /reports-admin/top-midias
Arquivo: reports-top-midias-admin.tsx
API: GET /api/reports/summary ou period-summary (campo topMedia)
Colunas: mídia, tipo, plays, tempo, % do total
Gráfico: bar horizontal top 10
Uso: conteúdo que mais engaja / mais gasta tempo de tela.

D) Disponibilidade — /reports-admin/disponibilidade
Arquivo: reports-disponibilidade-admin.tsx
API: GET /api/monitoring (+ se preciso GET /api/admin/global-stats)
Colunas: tela, cliente, status, lastSeen, tempo offline estimado, cidade/local
KPIs: % online agora, offline >2h, never connected
Uso: SLA / operação de campo.

E) Locais — /reports-admin/locais
Arquivo: reports-locais-admin.tsx
API: GET /api/locations (admin global se existir; senão agregar de screens)
Colunas: local, cidade, qtd telas, online, offline, plays período (se joinável)
Uso: performance por praça/ponto.

F) Assinaturas — /reports-admin/assinaturas
Arquivo: reports-assinaturas-admin.tsx
API: GET /api/admin/operators + GET /api/admin/financial
Colunas: cliente, status, trialEndsAt, telas, preço/tela, mensalidade, último pagamento
KPIs: MRR, trials ≤7d, suspensos, pendentes
Uso: retenção e cobrança.

G) Atividade — /reports-admin/atividade
Arquivo: reports-atividade-admin.tsx
API: logs/activity do admin (ex.: /api/logs ou activity table com requireAdmin)
Colunas: data, usuário/cliente, ação, entidade
Filtros: período, tipo de ação
Uso: auditoria de quem fez o quê.

H) Armazenamento — /reports-admin/armazenamento
Arquivo: reports-armazenamento-admin.tsx
API: operators + storageQuotaGb; se possível endpoint admin com bytes usados por cliente
Colunas: cliente, usado GB, quota GB, %, qtd arquivos
KPIs: clientes ≥80%, ≥100%
Uso: upsell de quota / limpeza.
